# LP Builder（ランディングページ作成）

参考サイト・参考画像をもとに、日本語のコンバージョン型LPを単一HTMLで作るためのスキル。
「参考を分析 → 独自デザインに翻訳 → 実装 → 実レンダリング検証」を1サイクルで回す。

## 成果物の形

- **単一の `index.html`**（CSS・JSを内包。読み込む外部リソースはWebフォントのみ）
- 画像は `assets/img/` にダウンロードして同梱（外部ホスト依存を作らない）＋ `CREDITS.md`
- レスポンシブ／モバイル固定CTA／`prefers-reduced-motion` 尊重

## ワークフロー

### 1. 参考を分析する

- **URLが与えられた場合**：WebFetchで構成（各セクションの見出し・訴求・料金・CTA・配色）を抽出する。
- **画像が与えられた場合**：Readで画像を見て、配色・レイアウト・タイポ・CTAの形を言語化する。
- 参考の「型（セクション順・訴求パターン）」は踏襲しつつ、**コピーと配色は独自に**組む
  （丸パクリしない／量産AIの「白地＋青見出し＋オレンジ丸ボタン」を避ける）。

### 2. 題材を1つに固定し、デザインを決める

- 何のサービスのLPかを具体的に決める（曖昧なら短く確認 or 妥当な仮定を置いて宣言する）。
- **パレット（4〜6色）／タイポ（見出し＝characterfulなJP gothic、本文＝Noto Sans JP、数値＝Outfit等）／
  レイアウト**を先に決めてから実装する。`artifact-design` スキルの原則を併用してよい。
- ヒーローの方向性は `references/hero-patterns.md` から選ぶ（切り抜き人物×背景色／極太数値／
  写真カード等）。参考画像に寄せる指示なら、その構図を最優先で再現する。

### 3. 実装する（セクション標準構成）

上から順に、必要なものを組む（参考に合わせて増減する）：

1. スティッキーヘッダー（ロゴ＋ナビ＋CTAボタン）
2. **ヒーロー**（最重要。`references/hero-patterns.md` 参照）
3. 実績・利用企業（社会的証明）
4. サービス紹介（画像＋説明。コラージュ可）
5. 特長（3〜4枚のカード）
6. 安心/信頼の帯（濃い背景色でリズムを作る）
7. 料金（成果報酬型などを表で）
8. 利用フロー（本当に順序があるときだけ番号付き）
9. 導入事例（数値付き）
10. FAQ（`<details>` アコーディオン）
11. 最終CTA（濃い背景＋大見出し）
12. フッター（会社情報・リンク）
13. モバイル固定CTAバー

実装の要点：
- セクション背景色を交互に切り替えてリズムを作る（隣接で同色を続けない）。
- レイアウトは flex/grid + `gap`。要素ごとの個別marginで組まない。
- スクロールリビール（IntersectionObserver）とヒーローの数値カウントアップは各1箇所程度に留める。
- `prefers-reduced-motion: reduce` で `.reveal` を即表示・アニメ停止にする。
- キーボードフォーカスの可視化、`<img>` に alt と width/height。
- 装飾モチーフ（紙吹雪・市松・ホログラム等）を足すなら `references/decorative-motifs.md` でトーンに合うものを選ぶ。主役を邪魔しない範囲で、同時に強く出すのは最大2種まで。

### 4. 画像を用意する

`references/image-pipeline.md` の手順で、フリー素材の取得・背景除去・クレジット記載を行う。
要点：Pexels/Unsplash からダウンロードして同梱、必要なら `rembg` で人物を切り抜き、
`assets/img/CREDITS.md` に出典を残す。

### 5. 必ず実レンダリングを確認する

ヘッドレスブラウザ（Playwright Chromium）で**デスクトップとモバイルの両方**を撮って目視する。
スクロールリビールで空白に見えるのを避けるため、検証時は `reducedMotion: 'reduce'` を有効化する
（本番CSSの reduced-motion 分岐で `.reveal` が即表示になる）。`references/image-pipeline.md` の
「レンダリング検証」に実行スニペットあり。

チェック：ヒーローの見出し・写真・数値の重なりが崩れていないか／モバイルで負マージンが効きすぎて
顔や文字に重なっていないか（重なり量は px 固定でなく **幅に対する % **にすると縦横比が保たれ破綻しにくい）／
セクションの色リズム／CTAの視認性／横スクロールが出ていないか。

## 守るべき原則

1. **参考の「型」は借り、見た目は独自に。** コピー・配色・タイポは作り込む。テンプレ顔を避ける。
2. **ヒーローに一番投資する。** 最初のスクリーンで価値と次の行動が伝わること。
3. **重なり・オーバーラップは % 指定。** 縦横比が固定なら幅%の負マージンで比率が保たれ、モバイルでも破綻しにくい。
4. **自己完結。** 画像は同梱、外部JS/CSSは使わない（フォントのみ）。CSPの厳しい環境でも動く。
5. **出したら必ず見る。** ソースだけで完成としない。デスクトップ＋モバイルをレンダリングして確認・調整する。

詳細な実装パターンは以下の参照ファイルに統合してある（LP制作で確立した技術の総まとめ）。
実装時はまず `build-guide.md` を開いて土台をコピーし、必要に応じて各専門ファイルを参照する：

- `references/build-guide.md` — **統合スキャフォールド**。デザイントークン設計、フォント選び、リセット、
  セクションの色リズム、ボタン各種、共通部品（ヘッダー/タブナビ/カード/料金/FAQ/事例/最終CTA/モバイル固定CTA）、
  モーション（reveal＋カウントアップ）、標準セクション順、仕上げチェックリスト。新規LPはここから始める。
- `references/hero-patterns.md` — ヒーロー構図：A切り抜き人物×背景色（フルブリード＋下端フェード＋%オーバーラップ）、
  B極太数値、C写真カード、D背景動画/動画差し込み、共通のグラデCTA＋吹き出しラベル＋No.1バッジ。
- `references/image-pipeline.md` — フリー素材の取得（Pexels/Unsplash/動画はMixkit）・背景除去（rembg）・
  クレジット・**ヘッドレス検証**（Playwright導入手順とトラブル対処、動画時の`load`待機）。
- `references/decorative-motifs.md` — 装飾モチーフ（バルーンテキスト／ウォータードロップ／ドゥードゥル／
  市松模様／ホログラム／コンフェッティ／モーションブラー）のメリット・活用シーン・実装ヒント（同時全開は最大2種）。

### 関連スキル
